# Studio Ghibli — Internationalization Take-Home (Starter)

This repository is the **starter** for the Studio Ghibli internationalization
take-home. It contains a small, working Studio Ghibli web app that currently ships
in **English only**:

- a **Welcome** screen with a short studio overview, and
- a **Movies** screen that fetches film details (image, title, tagline, director,
  release date, runtime, score, and trivia) from a GraphQL backend.

Your job is to make the site **internationalization-ready**, using the translation
source material provided under [`translations/`](./translations). The full brief —
goals, what we're evaluating, and how to submit — is in the assignment:

📋 **[Assignment instructions → `STUDIO_GHIBLI_I18N_TAKEHOME.md`](./STUDIO_GHIBLI_I18N_TAKEHOME.md)**

There is **no internationalization in the app yet** — every string and every film
is English. The Markdown under `translations/` is source material only; no
application code reads it.

## What's in here

A [pnpm workspace](https://pnpm.io/workspaces) monorepo with two packages:

- **`packages/backend`** — a GraphQL API (GraphQL Yoga + Pothos + Express) that
  serves ten Studio Ghibli films from a PostgreSQL database. No external API is
  called at runtime. See [`packages/backend/README.md`](./packages/backend/README.md).
- **`packages/frontend`** — a React + Vite app (Apollo Client, MUI) with the two
  screens above, wired to the backend through typed hooks generated by GraphQL
  Code Generator. See [`packages/frontend/README.md`](./packages/frontend/README.md).

## System requirements

- **Node.js `24.7.0`** — the version pinned in [`.nvmrc`](./.nvmrc). With `nvm`,
  run `nvm install && nvm use` from the repo root.
- **pnpm `10.x`** — see the [pnpm install guide](https://pnpm.io/installation).
- **git**.
- **Docker** — required for the backend's **PostgreSQL** database (the films are
  stored in Postgres). Started via the provided `docker-compose.yaml`.
- macOS, Linux, or WSL.

## Getting started

From the repository root:

```bash
# 1. Use the pinned Node version
nvm install && nvm use        # or install Node 24.7.0 another way

# 2. Install all workspace dependencies (one install for both packages)
pnpm install
```

### Run the backend (terminal 1)

```bash
# from the repo root: start the PostgreSQL database
docker compose up -d

cd packages/backend
cp .env.example .env           # local config (PORT 8080, /api/graphql, DATABASE_URL)
pnpm generate                  # generate the Prisma client + schema.graphql
pnpm migrate                   # create the database tables
pnpm seed                      # load the ten films into the database
pnpm dev                       # start the GraphQL server
```

The API is now at **http://localhost:8080/api/graphql** (open it in a browser for
the GraphiQL explorer).

### Run the frontend (terminal 2)

```bash
cd packages/frontend
cp .env.example .env           # contains VITE_GRAPHQL_URL pointing at the backend
pnpm dev                       # starts the Vite dev server
```

Open **http://localhost:3000** — the Welcome screen loads; "View Movies" navigates
to the Movies screen, which fetches the films from the backend.

> The frontend's generated GraphQL hooks are committed, so it runs without a
> codegen step. After changing a GraphQL operation, run `pnpm codegen` (from
> `packages/frontend`) to regenerate them.

## How film data is served

Film data lives in **PostgreSQL** (the `film` table, via Prisma). The ten films are
a static dataset in `packages/backend/prisma/seed/films.data.ts`, loaded into the
database by the seed script (`pnpm --filter ./packages/backend seed`). The `films`
and `film(id)` GraphQL queries read from the database — no external API is called at
runtime.

## `translations/`

[`translations/`](./translations) holds Markdown source material for localizing the
app — general/static site copy across **20 languages**, plus per-film copy in the
subset of languages each film supports (coverage is intentionally uneven). These
files ship as raw material for the assignment and are **not** imported by any
application code. See [`translations/README.md`](./translations/README.md).

## Quality checks

The standard checks (mirrors CI):

```bash
pnpm --filter ./packages/backend generate   # Prisma client + schema.graphql
pnpm exec biome check .                      # lint & format
pnpm -r run type                             # TypeScript, all packages
pnpm exec knip                               # unused files / exports / deps
```
